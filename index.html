Gestão da configuração e SSH

Aula 1 · TP02
  • running-config está na RAM (perde-se ao reiniciar); startup-config está na NVRAM. Guardar: copy running-config startup-config.
  • enable secret guarda a palavra-passe com hash; service password-encryption só cifra (fraco) as que estão em texto.
  • SSH precisa de: hostname diferente de "Switch", ip domain-name, chaves RSA, utilizador local e vty só com SSH. Prefere-se ao Telnet porque cifra tudo, incluindo a palavra-passe.
  • Cópias de segurança: copy running-config tftp; repor com copy tftp running-config.
  • CDP (Cisco) e LLDP (norma) mostram os vizinhos: show cdp neighbors detail.
hostname Lisboa-ASW1
ip domain-name minhaempresa.pt
crypto key generate rsa          ! modulus 1024 ou mais
ip ssh version 2
username admin secret Cisco123
line vty 0 15
 login local
 transport input ssh

Pegadinha

Sem hostname e domain-name o crypto key generate rsa não funciona. Para SSHv2 a chave tem de ter pelo menos 768 bits (usa 1024).

Comutação e tabela MAC

Aula 2
  • O switch aprende o MAC de origem e a porta de entrada (tabela MAC/CAM, envelhece aos 300 s).
  • Destino conhecido: envia só para essa porta. Destino desconhecido, broadcast ou multicast: inunda todas as portas da mesma VLAN menos a de entrada.
  • Store-and-forward: recebe a trama toda, verifica o FCS e descarta as erradas; mais latência, permite velocidades diferentes.
  • Cut-through: começa logo após ler o MAC de destino. Fast-forward = só o destino (menor latência); fragment-free = lê os primeiros 64 bytes (apanha colisões).
  • Cada porta de switch é um domínio de colisão; cada VLAN é um domínio de difusão. Só um router (ou switch L3) separa domínios de difusão.

Conta rápida

Switch de 24 portas, todas usadas, uma VLAN: 24 domínios de colisão e 1 de difusão. Com 3 VLANs: 24 e 3.

VLANs

Aula 2 · TP03
  • Gama normal 1–1005 (guardadas em vlan.dat na flash); gama estendida 1006–4094. As 1002–1005 são reservadas.
  • Tipos: default (VLAN 1), dados, voz, gestão (943), nativa (999).
  • As VLANs dividem o domínio de difusão: hosts em VLANs diferentes só comunicam através de um equipamento de camada 3.
  • A gestão vai para uma VLAN própria (não a 1) para separar o acesso aos equipamentos do tráfego dos utilizadores.
  • VLAN de voz: a porta de acesso leva os dados sem tag e a voz com tag 802.1Q (o telefone tem um mini-switch e o PC liga-se atrás).
vlan 143
 name ADMIN-43
interface range fa0/1 - 8
 switchport mode access
 switchport access vlan 143
! voz (exemplo genérico)
 switchport voice vlan 150
show vlan brief

Pegadinha

Portas trunk não aparecem no show vlan brief. Apagar uma VLAN deixa as portas dela inativas até as mudares.

Trunks 802.1Q e DTP

Aula 2 · TP03
  • Trunk = uma ligação que transporta várias VLANs. O 802.1Q mete uma tag de 4 bytes (com o VLAN ID de 12 bits).
  • A VLAN nativa vai sem tag. No cenário é a 999, igual nos dois lados (se for diferente: native VLAN mismatch, o CDP avisa e há fuga de tráfego entre VLANs).
  • switchport trunk allowed vlan 543 substitui a lista. Para acrescentar usa allowed vlan add 543.
  • DTP: dynamic auto + dynamic auto = acesso; desirable + auto/desirable/trunk = trunk. Desliga-se com switchport nonegotiate (evita switch spoofing).
  • No 3650 é preciso switchport trunk encapsulation dot1q antes de switchport mode trunk; no 2960 não.
interface range gi0/1 - 2
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 143,243,343,443,943,999
 switchport nonegotiate
show interfaces trunk

Encaminhamento inter-VLAN

Aula 3 · TP04
  • Router-on-a-stick: um trunk até ao router e uma subinterface por VLAN com encapsulation dot1Q. Limitação: todo o tráfego entre VLANs sobe e desce o mesmo cabo.
  • Switch de camada 3: uma SVI por VLAN + ip routing. Mais rápido (hardware) e escalável. É o que o cenário usa.
  • Uma SVI fica up/up se a VLAN existe, há pelo menos uma porta ativa nela (acesso ou trunk) e tem no shutdown.
  • Porta encaminhada no 3650: no switchport e um IP (ligação /30 ao router).
! router-on-a-stick (fase A do TP04)
interface fa0/0.143
 encapsulation dot1Q 143
 ip address 10.43.1.1 255.255.255.0
! switch L3 (DSW1)
ip routing
interface vlan 143
 ip address 10.43.1.2 255.255.255.0
 no shutdown
interface gi1/1/1
 no switchport
 ip address 10.43.0.2 255.255.255.252

DHCPv4 e relay

Aula 3 · TP04
  • DORA: Discover (broadcast) → Offer → Request (broadcast) → Ack.
  • Concessão (lease): aos 50 % (T1) o cliente pede renovação ao mesmo servidor (unicast); aos 87,5 % (T2) pede a qualquer servidor (broadcast); no fim, perde o endereço.
  • Servidor noutra sub-rede: o router/SVI tem de fazer relay com ip helper-address, que transforma o broadcast em unicast e preenche o giaddr (assim o servidor escolhe o pool certo).
! router Lisboa
ip dhcp excluded-address 10.43.2.1 10.43.2.20
ip dhcp pool COMERCIAL-43
 network 10.43.2.0 255.255.255.0
 default-router 10.43.2.1
 dns-server 10.43.4.10
 domain-name minhaempresa.pt
! DSW1 (no DSW2 o helper é 10.43.0.5)
interface vlan 243
 ip helper-address 10.43.0.1
show ip dhcp binding

IPv6: LLA, EUI-64, SLAAC e DHCPv6

Aula 1/3 · TP02
  • Link-local (FE80::/10): criado sozinho em cada interface, só vale na ligação; é usado no NDP e como gateway (no cenário fe80::1).
  • EUI-64: parte o MAC ao meio, mete FFFE no meio e inverte o 7.º bit. 00:1A:2B:3C:4D:5E → 021A:2BFF:FE3C:4D5E. Muitos sistemas usam IDs aleatórios por privacidade (o MAC não fica exposto).
  • Flags do RA: A=1 SLAAC; O=1 DHCPv6 stateless (só DNS e afins); M=1 DHCPv6 stateful (o endereço vem do servidor).
  • O router só envia RAs com ipv6 unicast-routing.

STP: eleição, custos e papéis

Aula 4 · TP05
  • Sem STP, um ciclo dá tempestade de broadcast, tramas duplicadas e tabela MAC instável.
  • BID = prioridade (múltiplo de 4096, por omissão 32768) + VLAN ID (extended system ID) + MAC. Na VLAN 243: 32768 + 243 = 33011.
  • Root bridge = menor BID (prioridades iguais → menor MAC).
  • Root port (uma por switch não-raiz): menor custo até à raiz → menor BID do vizinho → menor port ID do vizinho.
  • Designated: uma por segmento, a do lado com menor custo. Alternate: alternativa à root port, fica a bloquear.
  • Custos (curtos): 10 Mb/s = 100, 100 Mb/s = 19, 1 Gb/s = 4, 10 Gb/s = 2. Custo do caminho = soma dos custos das portas de entrada até à raiz.
! DSW1 (o DSW2 faz o inverso)
spanning-tree vlan 143,343,943 root primary   ! fica 24576
spanning-tree vlan 243,443 root secondary     ! fica 28672
show spanning-tree vlan 243
show spanning-tree root

Ler o show

Num ASW1, na VLAN 243 (raiz DSW2): Gi0/2 = Root FWD; Gi0/1 = Altn BLK. Na VLAN 143 é ao contrário.

Temporizadores, RSTP, PVST+, PortFast

Aula 4 · TP05
  • 802.1D: hello 2 s, forward delay 15 s, max age 20 s. Uma porta bloqueada que deixa de receber BPDU demora ≈ 20 + 15 + 15 = 50 s a chegar a forwarding.
  • Estados 802.1D: blocking, listening, learning, forwarding (e disabled). RSTP (802.1w): discarding, learning, forwarding; converge em poucos segundos com propostas e acordos.
  • PVST+ / Rapid PVST+: uma instância por VLAN, por isso cada VLAN pode ter uma raiz diferente e a carga divide-se entre DSW1 e DSW2.
  • PortFast: a porta de acesso salta logo para forwarding. BPDU Guard: se chegar um BPDU nessa porta, passa a err-disabled. Usam-se juntos nas portas para hosts.
spanning-tree mode rapid-pvst
interface range fa0/1 - 16
 spanning-tree portfast
 spanning-tree bpduguard enable

EtherChannel

Aula 5 · TP05
  • Junta várias ligações físicas numa lógica (Po1): mais largura de banda, redundância, e o STP vê uma só porta (não bloqueia metade).
  • LACP (802.3ad, norma): active / passive. PAgP (Cisco): desirable / auto. on = estático, sem negociação.
  • Forma canal: active+active, active+passive, desirable+desirable, desirable+auto, on+on. Não forma: passive+passive, auto+auto, ou misturar LACP com PAgP.
  • LACP: até 16 portas configuradas, 8 ativas. As portas têm de ter a mesma velocidade, duplex, modo e VLANs.
interface range gi1/0/23 - 24
 channel-group 1 mode active
interface port-channel 1
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk native vlan 999
show etherchannel summary     ! bom: Po1(SU) e portas (P)

Flags

S = camada 2, U = em uso, P = agregada. Mau sinal: D (down), I (stand-alone), s (suspensa).

FHRP e HSRP

Aula 5 · TP06
  • Problema: os PCs só têm um gateway. Um FHRP dá um IP e um MAC virtuais partilhados por dois routers/switches L3.
  • HSRP: um Active responde ao IP virtual, um Standby espera. Estados: Initial → Learn → Listen → Speak → Standby → Active.
  • Prioridade por omissão 100; ganha a maior; empate → maior IP. Sem preempt, quem volta não recupera o papel.
  • Hello 3 s, hold 10 s. MAC virtual: v1 0000.0C07.ACxx (grupo em hex, até 255); v2 0000.0C9F.Fxxx (até 4095).
  • HSRP e VRRP: um ativo de cada vez (VRRP é norma, "master/backup"). GLBP (Cisco) divide a carga por vários gateways ativos.
  • Active/Active nos dois DSW = não recebem os hellos um do outro (p. ex. a VLAN não passa no Po1).
! DSW1, VLAN 143 (ativo)
interface vlan 143
 ip address 10.43.1.2 255.255.255.0
 standby version 2
 standby 143 ip 10.43.1.1
 standby 143 priority 110
 standby 143 preempt
show standby brief

Port security, DHCP snooping e DAI

Aula 6 · TP06
  • Port security: maximum (por omissão 1), sticky (os MACs aprendidos vão para a running-config; guarda com copy run start).
  • Violação: shutdown (omissão, porta err-disabled), restrict (descarta, regista e conta), protect (descarta sem registar). O plano usa restrict, máximo 2.
  • Recuperar de err-disabled: shutdown e depois no shutdown.
  • DHCP snooping: portas untrusted por omissão; trust nos uplinks Gi0/1–2 (por onde vêm as respostas legítimas). Cria a tabela de bindings.
  • A DAI usa essa tabela para validar os ARP; também com trust nos uplinks.
interface range fa0/1 - 16
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
 ip dhcp snooping limit rate 10
ip dhcp snooping
ip dhcp snooping vlan 143,243,343
ip arp inspection vlan 143,243,343
interface range gi0/1 - 2
 ip dhcp snooping trust
 ip arp inspection trust

Wi-Fi com WLC

Aula 7 · TP07
  • AP autónomo configura-se um a um; AP lightweight (LAP) é gerido por um WLC através de um túnel CAPWAP.
  • O WLC liga-se por trunk (ASW3 Fa0/21, nativa 999); os LAP ligam-se a portas de acesso da VLAN 943.
  • Dois SSIDs: colaboradores → VLAN 343; convidados → VLAN 543. Ambos WPA2-PSK com AES. O WPA3 troca o PSK por SAE (mais seguro contra ataques de dicionário).
  • Bandas: 2,4 GHz (canais 1, 6 e 11 não se sobrepõem) e 5 GHz (mais canais, menos alcance).
vlan 543
 name WIFI-CONV-43
interface range gi1/0/1 - 3
 switchport trunk allowed vlan add 543
interface vlan 543
 ip address 10.43.5.2 255.255.255.0
 standby version 2
 standby 543 ip 10.43.5.1
 standby 543 priority 110
 standby 543 preempt
